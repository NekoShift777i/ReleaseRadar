ReleaseRadar — Changelog
========================

Version 1.2.0 — preparing for release
-------------------------------------

Added:
- Manual checks for individual software entries using Telegram buttons.
- Paginated software selection in the /check command.
- Parallel checks for multiple software entries.
- Validation of configuration structure and parameters.
- Configurable notification button lifetime.
- Automatic cleanup of expired buttons and service records.
- Skipping individual releases with a reason.
- Persistent skipped-release history in SQLite.
- The /skipped command to view skipped-release history.
- Additional automated tests for core functionality.
- Tracking for Actual Budget, Frigate NVR, and HeliBoard.

Improved:
- Authorization checks for Telegram commands and button presses.
- Protection against concurrent checks of the same software entry.
- Release retrieval error handling and status display.
- Safe editing of existing Telegram messages.
- Version comparison and selection of suitable releases.
- Protection against repeated button presses and expired buttons.
- Independent cancellation of confirmation and skip requests.
- Exclusion of skipped releases from repeated notifications.
- Display of skip dates in Kamchatka local time.
- Installation, configuration, and maintenance documentation.

Fixed:
- Several errors when saving state in SQLite.
- Duplicate check requests for the same software entry.
- Handling of expired confirmation requests.
- Old buttons can no longer cancel a newer skip request.

Database changes:
- Added the created_at field for notification buttons.
- Implemented schema updates for existing databases.
- Added a table for skipped-release history.

Notes:
- Confirming an update changes the stored version but does not install
  the software.
- Backing up the SQLite database before upgrading is recommended.
- Skipped-release history persists across restarts.

Version 1.1.1
-------------

Added:
- The release_filter parameter for choosing how GitHub releases are filtered.
- Support for strict, github, and version filtering modes.

Improved:
- Handling of temporary Telegram network errors.

Fixed:
- Excessive traceback output when Telegram connections fail.

Version 1.1.0 — 2026-11-01
--------------------------

Added:
- Optional personal GitHub access token through the GITHUB_TOKEN variable
  in .env. Requests are unauthenticated when no token is provided.
- The /pending command to resend notifications about unconfirmed updates,
  including a "Version updated" button.
- Built-in Telegram command menu with descriptions of available commands.
- The packaging library for version comparison.

Improved:
- config.yaml error messages now include the software[N] entry index and,
  when available, the software name and identifier.
- Log protection: known secrets are redacted from messages and exceptions;
  httpx and httpcore logging verbosity is reduced.
- GitHub update detection: the stable channel now selects the highest
  stable version from the release list rather than relying solely on
  the release marked as latest by GitHub.

Fixed:
- An older version should no longer be treated as a new update merely
  because the version strings differ.
- Separate handling for GitHub authentication and rate-limit errors.

Notes:
- After updating dependencies, run:
  pip install -r requirements.txt
- Existing log entries containing secrets are not cleaned automatically.
- Resending a notification does not change the stored current version.

Version 1.0.1 — 2026-10-25
--------------------------

Fixed:
- Handling of the SIGTERM signal when shutting down ReleaseRadar.

Version 1.0.0 — initial release
-------------------------------

- Software update tracking through GitHub and GitLab.
- Configuration of tracked software through config.yaml.
- Periodic update checks.
- Telegram notifications with update confirmation.
- Persistent state for tracked software.
- Commands for checking updates and viewing status.
- Operation as a Linux service.

Note: The exact date of the initial release is not specified here.
